# 対象範囲と互換性

## 製品責務

`skills-reconcile` の新しい責務は、既知のローカルディレクトリから Skill を発見し、利用者が選択した
Skill を自分のリポジトリへ取り込めるようにすることである。

Skill の作者や導入経路は、管理可否を決める属性にしない。自作 Skill も、第三者作成 Skill も、
利用者が取り込み対象として選ぶ候補である。ツールはライセンスの適合性を判定せず、選択した内容を
管理する責任は利用者が負う。

## 現在の実行前提

| 前提       | 現在の決定                         |
| ---------- | ---------------------------------- |
| 実行場所   | 利用者のローカルマシン             |
| 最初の入力 | `$HOME/.agents/skills`             |
| 状態境界   | ローカルファイルシステムの読み取り |
| 最初の出力 | 発見した Skill の一覧              |
| 書き込み   | なし                               |
| 外部 CLI   | 使用しない                         |
| 作者区分   | 判定しない                         |

## 最初の実装範囲

最初のマイルストーンは、`.agents/skills` にある Skill を読み取り専用で一覧表示することだけを扱う。
Skill の認識条件、symlink、異常 entry、並び順、出力形式は、先行する N01 の CLI 契約で確定する。

実装は、実 HOME を必要としない filesystem discovery の責務と、利用者向け CLI の責務を分ける。
テストは一時ディレクトリに作成した合成 Skill だけを使用する。

## 最初の実装に含めないもの

- 自作 Skill と第三者作成 Skill の分類
- `skills add`、lockfile、導入 provenance の解析
- frontmatter の内容解析
- `.agents/skills` 以外の走査
- 設定ファイルによる走査 root の追加
- TUI、検索、フィルタリング、選択
- リポジトリへのコピー
- コピー先の directory layout
- 上書き、更新、削除、rollback
- Git commit、push、複数マシンへの配布

## 将来の責務境界

一覧表示の次は、次の順で判断する。

1. 走査対象にするディレクトリを決める。
2. 複数の配置先から得た Skill を一つの TUI で表示し、フィルタリングできるようにする。
3. コピー先リポジトリの構造と、同名 Skill の衝突規則を決める。
4. 選択した Skill を安全にコピーする。
5. リポジトリから別マシンまたは各 Agent へ反映する方法を決める。

各段階は、前段の実装を変更しなくても拡張できるという仮定では進めない。必要になった責務だけを、
その時点の契約に基づいて追加する。

## 互換性

旧ロードマップ、旧 manifest schema、旧 command 候補、`skills-sync` との互換性は提供しない。
リポジトリ内の既存コードや package 境界も互換対象にしない。

CLI 名と Go module は、別の決定がない限り `skills-reconcile` と
`github.com/y-writings/skills-reconcile` を使用する。

## 最初の完了条件

- N01 で一覧表示の CLI 契約が承認されている。
- 合成した空、単一、複数、異常 entry の fixture で discovery の挙動が固定されている。
- CLI が契約どおりの一覧、終了 status、stdout/stderr を返す。
- 実行前後で対象 tree が変化しない。
- 旧方針だけに必要だった runtime dependency を一覧表示経路が使用しない。
- Go、Nix、コンテナの提供経路が、新しい最小 CLI に対して検証されている。
